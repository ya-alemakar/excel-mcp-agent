# Отчёт о выполнении

Дата: 23 ноября 2026 года. Данные вымышленные.

Выбран готовый [Excel MCP Server от haris-musa](https://github.com/haris-musa/excel-mcp-server), версия PyPI 2.3.3. Причины: локальные XLSX без Microsoft Excel, чтение диапазонов, запись новых строк и редактирование отдельных ячеек, stdio и ограничение рабочей папки. Собственный MCP-сервер не создавался.

Создан лист «Заявки» в requests.xlsx с четырьмя столбцами и исходными заявками №101–103. Создание и все последующие операции выполнялись через MCP. Приложение использует официальный JS MCP SDK. Зависимость openpyxl принадлежит установленному стороннему серверу; код приложения её не вызывает.

Создан браузерный интерфейс: чат, таблица, обновление, карточка подтверждения, таблица результатов поиска и подробный журнал MCP. LLM работает в eve и самостоятельно выбирает клиентские инструменты чтения, добавления и подготовки изменения.

## Реальные результаты сквозной проверки

| Сценарий | Проверенный результат |
| --- | --- |
| Добавить Анну Смирнову | Создана №104 с проблемой «ноутбук сильно тормозит» и статусом «Новый» |
| Подготовить изменение | Агент назвал №104, клиента, проблему и переход «Новый» → «В работе»; до подтверждения данные не изменились |
| Подтвердить изменение | Записана только D5; повторное чтение подтвердило статус и неизменность остальных строк и полей |
| Список «В работе» | Две записи: №102 Мария Соколова и №104 Анна Смирнова |
| Изменить №999 | «Заявка №999 не найдена. Ничего не изменено» |
| Добавить Дмитрия без проблемы | «Какая проблема возникла у Дмитрия?»; новая строка не создана |

Пример цепочки добавления: сообщение пользователя → выбранный моделью `excel__read_requests` → MCP `read_range` → модель вычисляет ID 104 → `excel__add_request` с `suggestedId: 104` → повторный `read_range` и проверка ID → `write_range` с `at: A5` и строкой `[104, "Анна Смирнова", "ноутбук сильно тормозит", "Новый"]` → `read_range` → ответ о создании. При подтверждении изменения `write_range` получает `at: D5`, `rows: [["В работе"]]`.

Полное доказательство: `artifacts/agent-check.json` (`mode: real LLM + stdio Excel MCP`, `ok: true`), включая сообщения, события выбора инструментов, настоящий MCP-ответ и финальные строки. Параметры и результаты всех MCP-вызовов также записываются в `artifacts/mcp-trace.jsonl` и показываются в приложении.

`npm run check` прошёл. `npm test` прошёл на отдельной книге artifacts/integration.xlsx: создание, добавление №104, отсутствие записи до подтверждения, проверка смены статуса, фильтр, несуществующий ID, неполные данные, чужой и повторный токен, отмена, конфликт записи и параллельные добавления с разными ID.

Рабочая книга оставлена после демонстрации: четыре заявки, включая Анну №104 «В работе». Начальные три заявки сохранены. Повторное нажатие «Добавить Анну» создаст следующую заявку; это действующая операция, а не демонстрационная заглушка.
