# Описание проекта: AI-агент для работы с Excel через MCP

Приложение помогает сотрудникам компьютерной мастерской вести заявки командами на русском языке. В браузере доступны чат, таблица заявок, обновление данных, подтверждение смены статуса и журнал MCP-вызовов. Используется локальный файл `requests.xlsx`, лист «Заявки», столбцы: ID, Клиент, Проблема, Статус. Все демонстрационные данные вымышлены.

## 1. Выбранный MCP-сервер

Используется готовый **Excel MCP Server** от **haris-musa**, пакет `excel-mcp-server`, установленная версия **2.3.3**.

- Репозиторий: https://github.com/haris-musa/excel-mcp-server
- Документация инструментов: https://github.com/haris-musa/excel-mcp-server/blob/main/TOOLS.md

Сервер выбран потому, что поддерживает локальные XLSX-файлы, чтение и запись диапазонов, изменение отдельных ячеек и создание книг. Для работы не требуется установленный Microsoft Excel. Собственный MCP-сервер в рамках проекта не разрабатывается.

## 2. Используемые инструменты MCP

| Инструмент готового сервера | Назначение в проекте |
| --- | --- |
| `read_range` | Чтение заявок, поиск нужной записи, получение ID, проверка результата записи |
| `write_range` | Добавление новой заявки в следующую свободную строку и изменение ячейки статуса |
| `create_workbook` | Первоначальное создание `requests.xlsx` с листом «Заявки» |
| `set_sheet_layout` | Настройка ширины столбцов и закрепление строки заголовков при создании файла |

При повторной проверке демонстрации также применялся `clear_range` для очистки ранее созданной тестовой строки после сверки данных. В обычном интерфейсе удаления заявок нет.

Модель получает три клиентских инструмента приложения. Они вызывают готовый MCP-сервер и добавляют проверки предметной области:

| Инструмент агента | Действие |
| --- | --- |
| `excel__read_requests` | Прочитать актуальные записи через `read_range`, при необходимости отфильтровать их по статусу |
| `excel__add_request` | Проверить предложенный моделью ID, добавить строку через `write_range`, перечитать результат |
| `excel__propose_status` | Найти запись через `read_range` и подготовить смену статуса для подтверждения человеком |

Эти инструменты являются клиентскими обёртками, а не отдельным MCP-сервером. Агент самостоятельно выбирает их по смыслу сообщения пользователя.

## 3. Подключение агента к MCP

Приложение написано на Node.js, AI-агент работает в runtime **eve**. Для MCP используется официальный JavaScript SDK `@modelcontextprotocol/sdk`.

Сервер установлен в локальное Python-окружение `.venv`. MCP-клиент запускает его отдельным процессом:

```text
.venv/Scripts/excel-mcp-server.exe stdio --allow-dir <папка проекта>
```

Подключение реализовано в `lib/mcp.mjs` через `Client` и `StdioClientTransport`. Обмен MCP-сообщениями идёт через стандартные потоки ввода и вывода процесса. HTTP-порт для Excel MCP не нужен. Параметр `--allow-dir` ограничивает доступ сервера папкой проекта. Соединение создаётся при первом обращении и используется повторно.

Агент вызывает серверную часть приложения через внутренний HTTP-маршрут `/internal/excel`, защищённый случайным токеном, который создаётся при запуске. Серверная часть выполняет проверки и отправляет настоящий MCP-запрос через `client.callTool({ name, arguments })`. Ключ модели остаётся на сервере и не передаётся браузеру.

Общая последовательность:

```text
Команда пользователя в браузере
    → LLM-агент eve выбирает инструмент
    → клиентская обёртка и проверки приложения
    → MCP tools/call по stdio
    → готовый Excel MCP Server
    → локальный requests.xlsx
    → результат MCP
    → ответ агента и обновление интерфейса
```

## 4. Чтение и изменение Excel-файла

### Чтение

`readRequests()` в `lib/requests.mjs` вызывает `read_range`, передавая абсолютный путь к книге, имя листа «Заявки» и размер страницы `max_cells: 2000`. Если сервер возвращает `next_range`, приложение запрашивает следующие страницы.

После чтения проверяются заголовки, уникальность числовых ID, заполненность полей и допустимость статусов. Фильтрация по статусу и подсчёт выполняются в JavaScript по данным, полученным через MCP. Кнопка «Обновить данные» также заново читает файл через MCP.

### Добавление заявки

1. Агент проверяет, что пользователь указал клиента и проблему. Если проблемы нет, задаёт уточняющий вопрос без добавления строки.
2. Модель вызывает `excel__read_requests`, получает актуальные ID и предлагает следующий ID по правилу `max(ID)+1`.
3. При вызове `excel__add_request` сервер повторно читает книгу и проверяет предложенный ID. Если данные успели измениться, запись отклоняется и требуется новое чтение.
4. Приложение вызывает `write_range` с начальной ячейкой следующей строки и значениями `[ID, Клиент, Проблема, "Новый"]`.
5. Повторный `read_range` подтверждает появление заявки и неизменность исходных строк. Только после проверки возвращается результат об успешном добавлении.

Например, после исходных заявок №101–103 новая заявка записывается с ID 104 в диапазон A5:D5.

### Изменение статуса

1. Агент вызывает `excel__propose_status`. Приложение читает Excel через MCP и ищет заявку по ID или точному имени клиента.
2. Если запись не найдена, агент сообщает об этом, запись в файл не выполняется. Если совпадений несколько, требуется уточнить ID.
3. Для найденной заявки показываются ID, клиент, проблема, текущий и предлагаемый статусы. Файл на этом этапе не меняется.
4. Пользователь нажимает «Подтвердить изменение» или «Отмена». Подтверждение одноразовое, привязано к чату и действует 10 минут. У модели нет инструмента, позволяющего самостоятельно подтвердить изменение.
5. После подтверждения сервер заново читает книгу и сравнивает запись с показанной пользователю. Если запись изменилась, операция отклоняется.
6. `write_range` изменяет только ячейку столбца D соответствующей строки. Например, для заявки №104 в строке 5 передаются `at: "D5"`, `rows: [["В работе"]]`.
7. Повторное чтение проверяет новый статус и неизменность остальных строк и полей.

Операции приложения выполняются последовательно в общей очереди. Внешние изменения из Microsoft Excel не участвуют в этой очереди, поэтому одновременное редактирование книги вручную следует исключить.

### Журнал и обработка ошибок

Для каждого реального MCP-вызова сохраняются название инструмента, параметры, источник вызова, время, результат и ошибка. Журнал доступен в браузере, выводится в консоль и записывается в `artifacts/mcp-trace.jsonl`.

Приложение не читает и не изменяет XLSX напрямую через `openpyxl` или `pandas`. Всю работу с содержимым книги, включая первоначальное создание и проверку изменений, выполняет сторонний MCP-сервер. При ошибке записи или проверки пользователь получает сообщение и должен обновить таблицу перед повтором команды.
