# AI-агент для Excel через MCP

Локальное приложение мастерской: чат на русском, таблица заявок из `requests.xlsx`, кнопка обновления, подтверждение смены статуса и журнал настоящих MCP-вызовов.

## Выбранный MCP-сервер

Используется готовый [haris-musa/excel-mcp-server](https://github.com/haris-musa/excel-mcp-server), установленный из PyPI: **excel-mcp-server==2.3.3**. Он работает с локальными `.xlsx` без установленного Microsoft Excel, поддерживает чтение `read_range`, запись `write_range`, создание книги `create_workbook` и настройку листа `set_sheet_layout`. Добавление строки выполняется записью в следующий свободный диапазон; изменение статуса — записью в одну ячейку D. [Документация инструментов](https://github.com/haris-musa/excel-mcp-server/blob/main/TOOLS.md).

Приложение запускает установленный сервер по **stdio** официальным клиентом `@modelcontextprotocol/sdk`. `--allow-dir` ограничивает сервер папкой проекта. Собственный MCP-сервер не создаётся. В приложении нет чтения или записи Excel через pandas/openpyxl: эти библиотеки может использовать только сторонний MCP-сервер внутри своей реализации. Даже первоначальная книга создаётся через MCP.

## Установка и запуск в Windows

Нужны Node.js 24+, Python 3.11+ и интернет для модели. Проверено с Node.js 24.21.0 и Python 3.14.7.

```powershell
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env # только если .env ещё нет
npm run setup:excel
```

В `.env` укажите ключ модели:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-6.1-sol
```

Альтернатива — `AI_GATEWAY_API_KEY` и `AGENT_MODEL=openai/gpt-6.1-sol`. Если заданы оба ключа, используется OpenAI напрямую. Ключи остаются на сервере, `.env` исключён из Git. MCP ключа не требует; просмотр и обновление таблицы доступны без ключа LLM. API модели может тарифицироваться вашим провайдером.

```powershell
npm start
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Порт 3000 обслуживает приложение; порт 2000 — runtime eve. MCP общается через stdio и не занимает HTTP-порт. Остановка: Ctrl+C. После изменения `.env` перезапустите приложение.

`setup:excel` создаёт только отсутствующий файл и не перезаписывает существующие данные. Исходные строки: №101 Иван Петров / Ноутбук не включается / Новый; №102 Мария Соколова / Принтер не печатает / В работе; №103 Олег Иванов / Мерцает монитор / Готово. Все данные вымышлены. После выполненной демонстрации файл также содержит Анну №104 со статусом «В работе».

## Как работает агент

Цепочка: **пользователь → LLM в eve → выбранный инструмент агента → MCP tools/call → локальный requests.xlsx → результат MCP → ответ**.

Модель выбирает из трёх типизированных клиентских инструментов:

| Инструмент агента | Реальные вызовы стороннего MCP |
| --- | --- |
| `excel__read_requests` | `read_range`, включая следующие страницы при необходимости; фильтр и подсчёт по прочитанным строкам |
| `excel__add_request` | `read_range` → свободный ID = max(ID)+1 → `write_range` → `read_range` проверки |
| `excel__propose_status` | `read_range` → поиск по ID или клиенту → подготовка конкретной записи для подтверждения |

Это клиентские обёртки с проверками предметной области, а не MCP-сервер. LLM понимает естественный язык, выбирает действие, сначала читает все заявки и вычисляет max(ID)+1. Перед записью код снова читает книгу и проверяет предложенный моделью ID, обязательные поля и подтверждение. Регулярные выражения не заменяют модель.

На кнопке подтверждения сервер снова читает запись, сравнивает её с показанной пользователю, вызывает `write_range` только для D нужной строки и перечитывает всю таблицу. Проверяется новый статус и неизменность остальных значений. Подтверждение одноразовое, действует 10 минут и привязано к чату. Если запись изменилась, необходимо подготовить новое подтверждение. Модель не получает токен и не может вызвать изменение статуса напрямую. Кнопка «Отмена» не изменяет книгу. Операции внутри одного процесса выполняются последовательно.

## Демонстрация сценариев

На исходной книге:

1. **«Добавь заявку от Анны Смирновой: ноутбук сильно тормозит»** — появляется №104, «Новый». В журнале: чтение, запись A5:D5, проверочное чтение.
2. **«Измени статус заявки Анны Смирновой на „В работе“»** — агент показывает ID, имя, проблему и переход статуса. До кнопки **«Подтвердить изменение»** файл неизменен. После подтверждения: чтение, запись D5, проверочное чтение.
3. **«Покажи все заявки со статусом „В работе“»** — агент читает MCP и выводит количество 2, Марию №102 и Анну №104. Под ответом показана структурированная таблица результата. Верхняя таблица всегда показывает всю книгу.
4. **«Измени статус заявки №999 на „Готово“»** — «Заявка №999 не найдена. Ничего не изменено». Вызов записи отсутствует.
5. **«Добавь новую заявку от Дмитрия»** — «Какая проблема возникла у Дмитрия?» До ответа строка не добавляется. Можно продолжить описание в этом же чате.

Кнопки примеров отправляют обычные сообщения настоящей модели. Учтите: повторное добавление Анны создаст ещё одну заявку со следующим ID; для изменения при нескольких заявках одного клиента агент попросит ID.

Справа раскрывайте **«Параметры и результат»**: показаны настоящее имя MCP-инструмента, абсолютный путь, лист, ячейка/диапазон, переданные строки, сырой ответ и ошибка. Источники `agent`, `confirmation`, `verification`, `table-refresh` позволяют различать причины вызова. Полный журнал дублируется в консоль и `artifacts/mcp-trace.jsonl`; интерфейс показывает последние 200 вызовов.

## Проверки и результаты

```powershell
npm run check       # TypeScript
npm test            # настоящий MCP, отдельный artifacts/integration.xlsx
npm run check:mcp   # та же интеграционная проверка без LLM
npm run check:agent # все пять сценариев через запущенное приложение и настоящую модель
```

`check:agent` требует исходную книгу с ID 101–103 и намеренно не сбрасывает существующие данные. Для повторной демонстрации остановите приложение, сохраните текущую книгу под другим именем, выполните `npm run setup:excel`, запустите приложение и проверку снова. Проверка добавит Анну и подтвердит статус; это автоматический тест действий пользователя, а не обход механизма подтверждения в приложении.

Реальная сквозная проверка прошла 23.11.2026. В `artifacts/agent-check.json` сохранены сообщения модели, выбранные ею инструменты, подтверждение, MCP-вызовы и финальные строки; `ok: true`. Проверены обе ошибки с побайтовым сравнением JSON строк до/после. Интеграционные тесты также проверяют чужой/повторный токен, отмену, конфликт записи и разные ID при параллельных добавлениях. Сводка — `REPORT.md`.

## Файлы и ограничения

`agent/instructions.md` — поведение LLM; `agent/tools/` — инструменты агента; `lib/mcp.mjs` — официальный MCP-клиент и журнал; `lib/requests.mjs` — проверки операций; `server.mjs` — HTTP API и чат; `public/` — браузерный интерфейс; `requests.xlsx` — рабочая книга. `mcp-config.json` показывает эквивалентную конфигурацию готового MCP для внешнего клиента; приложению она не нужна, оно запускает сервер самостоятельно.

Приложение рассчитано на локальную учебную работу, без пользователей и сетевой публикации. После перезапуска чаты и неподтверждённые операции начинаются заново; файл Excel сохраняется. Не редактируйте книгу одновременно в Excel: внешний процесс не участвует в очереди приложения, а открытая книга может быть заблокирована Windows. При ошибке записи/проверки обновите таблицу перед повторной командой. Статусы ограничены «Новый», «В работе», «Готово»; повторяющиеся ID и неполные строки приводят к понятной ошибке вместо перезаписи.
